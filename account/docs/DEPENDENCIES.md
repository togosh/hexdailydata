# Dependency and authentication decisions

Resolved from the registry for this lab: Better Auth 1.7.5, Fastify 5.12.5, pg 8.23.0, React/React DOM 19.3.0, Nodemailer 10.0.10, Zod 4.6.5, TypeScript 7.0.2, Vite 8.3.0, Playwright 1.63.0. Exact direct versions and transitive integrity hashes are in the root lockfile; Node is 24.21.0. PostgreSQL, Mailpit and Node image digests are in `config/images.json`/`Dockerfile`.

Official sources read on 2026-09-19: [Fastify integration](https://better-auth.com/docs/integrations/fastify), [email/password and reset](https://better-auth.com/docs/authentication/email-password), [database/migrations](https://better-auth.com/docs/concepts/database), [rate limiting](https://better-auth.com/docs/concepts/rate-limit), and [published Better Auth advisories](https://github.com/better-auth/better-auth/security/advisories). The visible current advisories included SSO, magic-link/email-OTP, SCIM, OAuth-provider and Stripe-plugin issues; those plugins are not enabled. This was a targeted check, not a complete independent dependency audit. `npm audit` reported zero known vulnerabilities in the tested lockfile.

Better Auth owns password hashing, session tokens and reset-token consumption. Its installed source was inspected for verification-token behavior, reset-session revocation and rate-limiter storage. Settings explicitly require verification, disable auto-login and cookie session caching, use a 1-hour session, 30-minute verification token, 15-minute reset token, and revoke sessions on reset. The Fastify adapter allowlists the small public auth surface, validates canonical example.test addresses and redirects, strips session tokens from ordinary JSON, and adds an atomic SQL consumed-link fence for verification/reset replay. Unsupported auth routes and identity field injection are rejected. With IP tracking disabled, this Better Auth release bypasses its IP limiter; the operative lab limiter is the explicit Fastify shared 40-requests/minute/method gate over all auth routes. It has two fixed buckets and retains no caller IP. This is a single-process lab policy, not a distributed production throttle.

API keys deliberately use a small separate adapter: 32 cryptographically random bytes, a SHA-256 verifier, immutable account ownership, max three active keys, and SQL account-level quotas. There is no custom password/session cryptography and no per-key balance. HTTP cookies are HttpOnly/SameSite=Lax with a loopback-only HTTP exception. Production configuration is refused.

Third-party packages are installed unmodified with their distributed license/notice files retained in node_modules and the local image. No vendored third-party source or dependency directory is included in the source ZIP. React browser output is built locally from those packages. `npm ci --ignore-scripts` avoids dependency lifecycle scripts. Chromium/OS packages are downloaded from the Node image's Debian repositories during image build; the observed browser version and built image identity belong to run evidence, not a promise of bit-for-bit OS-package rebuilds.
