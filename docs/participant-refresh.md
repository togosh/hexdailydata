# Participant refresh operation

The normal API captures one immutable holder/stake/product selection per request. The accepted B0 stores and B1 overlay remain external, read-only prerequisites. Consecutive descriptors contain exact immediate-before and full after objects, bounded capture references, hash-pinned window identity, family identities and an independent saved-capture proof. They do not recursively include previous bundles.

Each update covers an inclusive changed-set window of at most 4,096 blocks. Four families page from their own beginning to explicit empty, repeat boundaries, resolve all independent end/Good Accounting parents, compare deterministic before/after witnesses and repeat paired headers. Only then may local admission publish one coordinated pointer. New population values are local represented row counts; a changed-set proof is not a complete target census, deletion propagation, reorg safety or current positive/active population qualification.

A request holds its original compatible view until both its handler and response settle. One local registry adopts a new pointer for all three views. Unknown ownership or incomplete product settlement blocks restart; only a known closed writer may reconcile its exact saved intent. No age-based unlock, public mutation endpoint, provider menu or automatic restart exists.

The maintained foreground entry point is:

    node scripts/participant-refresh.mjs run TASK_ROOT PREFLIGHT_JSON

It requires a new reviewed task root, exact frozen plan/runtime/source bindings, selected seed identities and a separately authorized finite session. It is not an indefinite service or a command to rerun a consumed task. The task trial wrapper additionally observes the same running loopback API across publications and closes all resources. Normal serving uses the existing product profile with the optional internal participantRoot; that path is an operator prerequisite, never a visitor parameter.

Participant storage is bounded to 50,000 cumulative holder keys, 50,000 cumulative stake keys, 32 MiB index, 256 MiB of persisted participant files and 4,096 descriptors. The census bases are never rewritten. Capacity refusal preserves the last selected view. Compact backup includes only new descriptors/segments and the small product backup; restoration still requires the exact external B0/B1 files. Future long-running reconciliation/checkpoint work and provider operating permission remain separate.
